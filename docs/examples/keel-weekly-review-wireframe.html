States

One wireframe per meaningful state. The scanning state is shown above — it is the entry state every week.

scanning
All clients expanded. Full open-work list visible. "Close week →" is present but dim — no action has been taken yet. This is the state shown above.
item closed
Tapping an open item marks it done: [·] flips to [✓], row dims, client open count decrements. Row stays in place until week is closed — the consultant can see what got done, not just what remains.
client collapsed
Tapping a client header collapses its item rows. Header and open count persist. Lets the consultant clear visual noise from clients already reviewed. "Close week →" activates only when all items across all clients are resolved or rolled.
roll unfinished
Triggered from "Close week →" if any [·] items remain. A sheet lists every open item with a binary choice: roll to next week, or mark dropped. This decision point is deferred until the consultant has finished scanning — it does not interrupt the review.
week closed
All items resolved or rolled. "Close week →" becomes "Week closed ✓". The week label advances to the next ISO week. Screen transitions to the new week's empty scanning state.

What the Next Step Confirms

✓ Hierarchy reads correctly at the scan distance the user arrives with — client name and open count register first, item detail second.
✓ Every state is structurally accounted for (Specifier turns this into the spec; the State Inventory enumerates them).
✓ "Close week →" is always visible in the action zone — no Buried Primary. It is gated by item state, not hidden behind a secondary action.
✓ Status dot + due day give enough per-item signal for a fast scan without requiring the consultant to open anything. The surface respects the time pressure of a weekly review.
